10. Conclusiones y Recomendaciones

Conclusiones

  1. El proceso de QA cumplió su objetivo: Se detectaron 10 defectos, 4 de ellos de severidad Alta/Crítica, que habrían representado un riesgo significativo de seguridad y consistencia si llegaban a producción sin ser detectados.
  2. El sistema tiene una base sólida: Las funcionalidades core (cálculo de ventas, descuento de stock, trazabilidad con Signals, transacciones atómicas, reset de contraseña, generación de PDFs) funcionan correctamente.
  3. El rendimiento es excepcional: La prueba con k6 (50 VUs concurrentes) resultó en un p90 de 7.54 ms, superando ampliamente el criterio de 1500 ms.
  4. OWASP ZAP no encontró vulnerabilidades críticas: El escaneo de seguridad validó que la aplicación no tiene fallos graves explotables de forma pasiva.
  5. La seguridad de la API requiere refuerzo urgente: Los defectos DEF-002 y DEF-005 exponen la API a accesos no autorizados y a escalada de privilegios. Son los hallazgos más importantes del reporte.
  6. Limitaciones del entorno: SQLite y Django 5.0.7/Python 3.14 impidieron ejecutar pruebas de concurrencia y de ciclo de backups de manera concluyente. Migrar a PostgreSQL y actualizar versiones resolverá estos hallazgos.

Recomendaciones

  1. Prioridad 1 (Bloqueante): Añadir permission_classes = [IsAuthenticated] a todos los ViewSets de crud_views.py.
  2. Prioridad 1 (Bloqueante): Añadir permission_classes = [IsAdminUser] al userViewSet y a todas las vistas de backup.
  3. Prioridad 1 (Bloqueante): Validar fortaleza de contraseña en el backend (mover la regex del frontend al serializer).
  4. Prioridad 2: Añadir min_value=0 a los campos numéricos de los serializers (stock, precios).
  5. Prioridad 2: Implementar constraint de unicidad en PurchaseOrder(invoice_number, supplier).
  6. Prioridad 3: Migrar de SQLite a PostgreSQL para producción y para pruebas de concurrencia.
  7. Prioridad 3: Actualizar Django a 5.2+ (o cambiar a Python 3.12/3.13).
  8. Prioridad 3: Añadir las cabeceras HTTP de seguridad en el proxy reverso.
  9. Prioridad 4: Añadir el enlace a "Gestión de Empleados" en el menú lateral.
Conclusión final: El proyecto "Fusión Solar" cuenta con una arquitectura sólida y una lógica de negocio bien implementada. Los 10 defectos detectados son corregibles y la mayoría se concentran en validaciones de seguridad y datos que no requieren rediseño. Una vez subsanados, el sistema estará listo para producción con un nivel de calidad y seguridad considerablemente superior al inicial.
